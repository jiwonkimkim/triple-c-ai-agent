### 좌측: Defect Flow Diagram

```
┌─────────────────────────────────────┐
│  📱 Chat UI (Next.js)               │
│                                     │
│  User: [이미지만 첨부하고 전송]      │
│  → message.content = ""             │
│  → message.attachments = [url]      │
└──────────────┬──────────────────────┘
               │
               ▼
┌─────────────────────────────────────┐
│  ❌ use-chat.ts 메시지 필터 (결함)   │
│                                     │
│  prev.filter(m => m.content.trim()) │
│  ↑ content=""이면 attachments       │
│    유무와 무관하게 메시지 제거       │
└──────────────┬──────────────────────┘
               │ 메시지 소실
               ▼
┌─────────────────────────────────────┐
│  📭 대화창에서 메시지가 사라짐       │
│  (사용자는 전송 실패로 오인)         │
└─────────────────────────────────────┘
```

**다크 코드 블록 (PNG 이미지 또는 코드 카드)**
```javascript
// ❌ Before — 결함 코드
prev.filter(m => m.content.trim())

// ✅ After — 수정 코드
prev.filter(m => {
  const hasContent = m.content.trim().length > 0
  const hasAttachments = (m.attachments?.length ?? 0) > 0
  return hasContent || hasAttachments
})
```

---

### 우측: 4단계 워크플로우 카드

**🔍 1. 현상 (Bug Detection)**
```
이미지만 첨부한 메시지 전송 후 AI 응답 수신 시
해당 메시지가 대화창에서 즉시 소실됨.
사용자는 전송 성공 여부를 확인할 수 없는 상태.
```

**🧠 2. 원인 분석 — 에러 추정(Error Guessing) 기법 적용**
```
"content가 빈 문자열인 경우 필터에서 제거될 수 있다"는
에러 추정 가설로 접근 → use-chat.ts의 메시지 필터 조건 확인.

content.trim()만으로 필터링하는 로직이
attachments를 가진 메시지를 동일하게 제거하는 것을 확인.
→ 조건 누락이 근본 원인.
```

**🔧 3. 해결 (Resolution)**
```
hasContent || hasAttachments 복합 조건으로 수정.
content가 없더라도 attachments가 존재하면 메시지를 유지.
수정 커밋: 12146b1
```

**🛡 4. 예방 — Playwright 자동화로 재발 차단**
```
TC-1.1: 이미지 전용 첨부 → AI 응답 후 메시지 visible 검증
TC-1.2: DB 재조회 경로(content="" + attachments=[url]) 표시 검증
TC-1.3: 텍스트+이미지 혼합 메시지 회귀 검증
TC-1.4: content=""·attachments=[] 빈 메시지 정상 필터 검증

→ tests/e2e/bug-prevention.spec.ts 자산화 완료
```
